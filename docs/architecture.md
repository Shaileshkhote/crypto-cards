# Architecture

`apps/admin` is Next.js with four admin screens and a separate read-only public cache API. Admin server actions call `core/jobs` and `core/review`. They never run extraction. `apps/worker` provides the CLI and long-running PostgreSQL job poller. Both use the same core functions; only the worker imports the job executor.

`packages/core` contains schemas, adapter loading, crawler, the universal OpenRouter tool loop, deterministic merge, sync, review, jobs, and cache projection. `packages/db` contains a thin parameterized SQL layer and transactional, advisory-locked migrations. There is no per-provider executable scraping code or additional queue service.

## Sync and publication

1. Validate all adapter files and source trust boundaries.
2. Fetch configured sources with robots checks, bounded global concurrency and per-domain serialization/delay. Discovery is disabled by default. Network failures update source health and preserve the last successful snapshot.
3. Normalize documents into stable content hashes and quoted blocks. HTML and Markdown tables keep headers with bounded groups of rows; a paragraph directly introducing a list stays with bounded groups of its rows so citations preserve plan, currency and period context; text PDFs use Poppler with preserved column alignment, a 20-second process timeout and bounded text output. Image PDFs remain pending transcription. Browser rendering is explicit and restricts scripts to trusted domains and content requests to configured URLs.
4. Look up per-source extraction fingerprints including model, provider, prompt, schema, parameters, adapter hints, and effective URL inventory. Static data is excluded, so static edits do not invalidate model work. Cached extractions must still satisfy current schema, completion, citation and financial checks. Invalid cache records become pending for re-extraction; accepted card data stays protected.
5. Run one bounded agent on the changed/missing extraction set. Its only tools are listPages, searchDocs, readPage. Repeated source text is referenced in earlier tool messages; a truncated search excerpt can still be expanded to a full block with readPage. Discovery requests go through the crawler, and discovered URLs are retained with source snapshots. The same publication validator checks the candidate inside that loop; at most two correction turns can address invalid targets or conflicting scopes. Invalid evidence, ambiguous same-block scopes, incomplete responses and over-budget work are rejected. Independently cited financial or country-list disagreements retain their source clauses as terms; disputed typed values are omitted unless reviewed source metadata declares explicit financial precedence. Complete multi-source responses must cover the financial preview blocks and explicit application-country lists. A response claiming the complete configured inventory with zero source facts is corrected or rejected; an empty incremental result remains valid when other configured sources are cached.
6. Verify source blocks and their financial numeric/currency evidence, assemble same-page collection rows, resolve known identities, and normalize rule IDs from provider/product/tier/kind/scope, monetary currencies and reward conditions. Add complementary feature observations across sources, keeping eligibility-list contradictions visible. Assemble source facts in deterministic order, then apply explicit static values.
7. Preserve unrelated accepted facts. Existing value edits and possible scope/identity replacements are held. Safe additions publish with a version check. Evidence accompanying held values stays pending too. Missing fields and rule values that no longer match fresh evidence remain present and are marked unconfirmed; fetch failure never implies absence or zero.
8. Insert the publication and immutable version in one transaction. A review records immutable changes and the base version. A new proposal supersedes the earlier review, including when the published base has not changed. Approval applies only those paths; rejection leaves the publication alone. Concurrent version changes prevent stale approval.
9. Rebuild all cache projections from committed cards in a separate transaction. Cache failures leave good publications intact and are reported as failures/mismatches until rebuilt.

The current cache rebuild scans all published providers; for a directory of roughly 50 providers this keeps it small and consistent without introducing cache infrastructure. Source extraction is incremental at document level. The extractor reconciles independently cited disagreements before strict candidate construction, preserving unrelated supported facts. Unqualified competing rules in one block still require correction. Reviewed `sources.metadata.supersedes` declarations apply only to matching financial claims; there is no automatic ranking by article date or source kind.

## Jobs and costs

A single worker claims jobs with `FOR UPDATE SKIP LOCKED`. PostgreSQL advisory locks serialize active jobs and per-provider syncs, including direct CLI invocations. The worker writes health heartbeats during long work. Interrupted jobs become failed after ten minutes and require an explicit retry; they are not silently recharged.

Each sync invocation owns one shared Budget: $4.50 by default, with a hard ceiling of $4.99 even when a larger override is supplied. The agent fetches current model prices, reserves a conservative byte-based input and maximum-output cost at the highest advertised pricing tier reachable by that request’s conservative input bound, including cache-write prices, before each request, and settles returned usage/cost. Requests with missing usage or uncertain network outcomes consume their reservation conservatively. An accounted timeout fails that provider and allows unrelated work to continue; typed budget/billing failures stop the job. No automatic request retries or provider fallback chain is used. A provider billing discrepancy stops the run; application estimates do not establish an absolute provider-side billing cap. Configure OpenRouter account/key spend limits too.

## Operational boundaries

Admin authorization is verified server-side by both the request proxy and every action. Basic auth uses constant-time digest comparison; Cloudflare Access mode verifies signature, issuer, audience, expiry, and allowlisted email. The browser never receives model credentials. Public cache routes export only GET; they do not expose pending candidates, jobs, or source snapshots.

Seven domain tables use JSONB for canonical payloads; an eighth `schema_migrations` table tracks operational migrations. Version history supports audit/rollback reconstruction, but is not a backup. See the off-host backup and restore procedure.
