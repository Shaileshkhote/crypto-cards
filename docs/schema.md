# Canonical schema

Runtime schemas and exported TypeScript types live in `packages/core/src/schema.ts`. All objects are strict. Schema and prompt versions participate in extraction fingerprints; update their constants after incompatible extraction changes.

Provider → products → tiers each support common feature fields. A fact belongs to its declared scope. Directory projections expose provider defaults, product defaults, and leaf facts separately. Ancestor fields are inherited only when listed explicitly in `inheritFields`, supported by source evidence or static data. Leaf values override inherited defaults. The agent defaults `inherit` to false; set it true only when the source explicitly applies the fact to every child. Lifecycle, retirement dates and external slugs belong to adapter configuration; model output cannot overwrite them.

Money is `{ amount: "10.50", currency: "EUR" }`. Strings preserve decimal precision; trailing decimal zeros are removed canonically. Rate fields use percentage points (`ratePercent: 1.5` means 1.5%). Countries must be real ISO 3166-1 alpha-2 codes. EU and EEA have centralized, distinct memberships. APAC, Europe, international and legacy region labels have no invented membership.

Fees discriminate on calculation: fixed requires money; percentage requires a nonnegative finite rate; tiered requires thresholds, inclusive flags, a period, and marginal/whole-amount behavior; unknown requires a description and `calculable: false`. Tiered thresholds increase in one currency and an unbounded threshold must be last. Fee applicability also distinguishes physical/virtual cards, first/additional issuance, payment rails and excluded transaction currencies. ATM withdrawals, declines and balance inquiries, delivery, refund processing, cross-border, late and returned payments, cancellation, formal chargebacks, declined purchases and small-transaction charges have distinct fee kinds. Services outside these kinds use `kind: other` with a required stable `serviceId`, such as `statement-copy`. Their supported price formula stays typed. A service outside the common kinds must not be mislabeled as an ordinary purchase fee. Weekday/weekend rates use explicit days of the week. Unsupported currency aliases and compound formulas remain narrative in non-calculable rules. The application retains the complete cited block for non-calculable descriptions, including prices and conditions; it does not invent coefficients or silently choose a formula. Rewards have scoped rates, assets, caps and requirements; non-calculable rewards retain narrative. Spending and ATM money limits retain amount, currency and period, including per-transaction limits. Transaction-count limits use a count instead of money. Unrepresentable limits keep narrative with calculable false. Terms and eligibility requirements remain available when they cannot be reduced safely.

Rule IDs are assigned by the core from hierarchy, rule kind, reward asset and requirements when applicable, the service identifier for `kind: other`, and applicability, never the value or position. Compatible observations sharing an identity combine their complementary fields, descriptions and all citations. Conflicting structured values sharing an identity fail extraction. Unsupported formulas retain the exact cited text as non-calculable rules, without guessed coefficients. A possible scope replacement is reviewed rather than silently replacing a rule. Unknown values never become 0; confirmed empty lists never become unknown.

Extracted feature origins are in `fieldSources`. Narrative terms and requirements from separate source blocks are additive. Other collection fields assemble rows from the same source page; complete lists from different pages must agree. Contributing origins are retained as an array. Financial rules still reject incompatible values/scopes. Tier scopes must identify real tiers and agree with the fact target. Rules carry one source or an array of contributing sources. Evidence is `{ url, blockId, quote }`; URL/block/substring must all match a cached normalized document. Financial amounts, rates and counts must also occur in that cited block; typed money requires a supported currency code, name or symbol in the evidence. This catches adjacent-row citations and invented fixed-money currencies, but does not prove every interpretation or omitted fact. Static origin is `{ origin: "static" }`. A valid quote proves the text exists, not its interpretation. Changes to existing values still require review. `unconfirmedFields` marks accepted values missing in changed source text. Fetch status and timestamps are stored outside canonical data.

Directory filters operate on typed leaf facts for residence, region, network, issuer, tier, physical/virtual, IBAN, KYC, currency, rewards and features. Uncommon services are excluded from generic numeric fee sorting because a shared service context is unavailable. Fixed and percentage fee displays retain conditions, minimums, maximums and allowances. Scoped numeric fee sorting requires residence country and transaction currency, excludes unconfirmed/ambiguous rules, and puts unknowns last. Fixed-money sorting compares only the explicitly requested currency using decimal string comparison. No currency conversion, effective spending calculation, or ranking is implemented.

Published JSON uses stable object keys, identity ordering, and string-set ordering. Timestamps and run metadata are excluded from canonical JSON. Bracket order is meaningful and preserved. The same accepted snapshots/static inputs produce the same bytes even when extraction cache records are grouped differently.
